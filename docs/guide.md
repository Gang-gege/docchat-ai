# DocChat 用法和原理（给前端看）

这份说明按页面操作来写。你不需要先懂机器学习。把它当成一个你熟悉的前后端项目：Vue 页面负责交互，Node 接口负责处理，SQLite 负责存数据，只有「让模型写答案」这一步会访问云上的大模型。

浏览器打开 **http://localhost:5173**。`localhost:3000` 是接口，没有页面。

---

## 1. 先建立一个整体画面

```text
你在浏览器里点的按钮
        │
        ▼
Vue 页面（frontend，5173）
  只负责：选文件、展示列表、把问题发出去、把流式文字画出来
        │  /api/...
        ▼
Node 服务（server，3000）
  负责：解析文件、切片、检索、决定要不要用工具、拼提示词、调模型
        │
        ├── 本机磁盘
        │     server/data/docchat.sqlite   文档、切片、向量、提示词、工作流
        │     server/storage/文档ID/原文件  上传的那份原件
        │
        └── 云上大模型（现在是 DeepSeek）
              只有生成回答、摘要、改写问句时才访问
```

和写普通后台的对应关系：

| 你熟悉的概念 | 在这个项目里是什么 |
| --- | --- |
| 前端页面 | `frontend/src/views/*.vue` |
| 请求封装 | `frontend/src/api/*.ts`，开发时 Vite 把 `/api` 代理到 3000 |
| 后端接口 | `server/src/routes/*.ts` |
| 业务逻辑 | `server/src/services/*.ts` |
| 数据库 | SQLite 文件，不是 MySQL，也不是假数据 |
| 登录用户 | 没有。这台电脑上的服务，就是这一份知识库 |

换一台电脑、只拉代码再启动：知识库是空的。文档在 `server/data` 和 `server/storage`，这两个目录不进 Git。对话记录更不在数据库里，而在当前浏览器的 `localStorage`，换浏览器也是空的。

---

## 2. 建议你这样用一遍

按这个顺序点，一遍就能把主链路走通。

1. **知识库**：上传一份 PDF、Markdown 或 TXT，点「开始入库」。表格里出现文档，切片数大于 0，就说明已经存进 SQLite。
2. **对话**：确认上面是「知识问答」，多轮记忆、查询改写先保持打开。问一个文档里真有的问题，例如「如何重置密码」。回答下面应能展开「引用来源」。
3. 接着问「那具体步骤呢」。因为多轮记忆开着，它知道「那」指的是上一问。回答上如果出现「改写检索：……」，说明系统把这句追问补成了一句完整的检索句。
4. 切到「智能体」，问「现在几点」或「知识库有哪些文档」。这次不一定引用文档，回答下会有工具过程。
5. 回到知识库，点同一行的「下载」。下来的是当时上传的原文件，不是切片拼出来的。
6. 右下角机器人再问一句。它和对话页共用上面那三个开关，但聊天记录是另一条，不会自动出现在对话页。点机器人标题栏的「对话页」，才会把当前这几条复制进一个新会话。

---

## 3. 对话页上那三个开关

对话页、右下角机器人、设置页里的「对话能力」，是同一组开关。在任何一处拨动，另外两处会一起变，并立刻记在这个浏览器里。

| 开关 | 打开时 | 关掉时 |
| --- | --- | --- |
| 知识问答 | 不走工具。问题直接拿去检索文档，模型只能根据查到的片段回答 | — |
| 智能体 | 先让模型判断要不要用工具。工具能回答（时间、文档数量、文档名单、在库里搜一句）就直接答完；判断这是文档问题，再回到知识库检索 | — |
| 多轮记忆 | 把当前这条会话最近几轮发给接口。追问「它」「上面那个」才有上文 | 每一问都当第一句，模型看不到你刚才说了什么 |
| 查询改写 | 必须同时开着多轮记忆，而且已经有上文。系统先把「那具体步骤呢」改写成「重置密码的具体步骤」，再用这句去检索 | 用你的原句去检索。第一句没有上文，本来也不会改写 |

这三个开关收在输入框里面，是底部的小胶囊。点开只显示当前选项，选完菜单会收起。对话页上还有三样机器人没有的东西，它们只作用于对话页当前会话：

- **回答风格**：输入框里的「标准 / 简洁 / 提纲 / 详解」小下拉。只影响模型怎么组织文字。
- **检索范围**：旁边的文档小下拉。显示「全部」就是不限制；选了某几篇，这次只在这几篇里找。
- **会话列表**：左侧栏。标签写在左侧栏底部。这些记录只在浏览器里。

设置页里的温度、TopK、相似度阈值、系统提示词，对话和机器人都会用。温度和提示词改完要点「保存到本地」。那三个开关不用再点保存。

## 4. 上传之后到底发生了什么

对应接口 `POST /api/upload`，代码在 `server/src/services/ingest.service.ts`。

1. 浏览器把文件交给 Node。
2. Node 读出纯文本。Markdown / TXT 直接读；PDF 用 `pdf-parse` 抽文字层（扫描件几乎没有文字，会失败，需要先导出成图片）；图片用本机 OCR。
3. 长文切成大约 800 字一块、相邻块重叠大约 120 字的片段。不切的话，整篇塞给模型又贵又容易超长度。
4. 每一块算一个向量。你现在的配置是**本地算法**，不算云上 Embedding，所以这一步不出网。
5. 两份东西一起留下：
   - 原文件复制到 `server/storage/文档ID/`，所以可以下载。
   - 文档信息和切片写入 `server/data/docchat.sqlite`。切片原文在 `chunks` 表，向量也在这张表里。

网页抓取是真的去请求你填的网址，去掉 HTML 标签后，把正文当成一个 `.txt` 入库。下载下来的是这段正文，不是原来的网页。

删除文档时，数据库记录和 `storage` 里的原文件一起删。

## 5. 你按下发送之后发生了什么

对话页和机器人最后都调用 `frontend/src/api/chat.ts` 里的 `openChatStream`，接口是 `POST /api/chat-stream`。服务端用 SSE 持续往回推文字，所以页面能一个字一个字地出来。编排在 `server/src/services/rag.service.ts`。

按「智能体」且开关打开时的顺序：

```text
你的问题
  → 智能体：模型看要不要调用工具
       用了工具 → 直接把工具结果说完，结束
       没有用工具 → 继续往下
  → 查询改写：有上文才做
  → 检索：问题变成向量，和库里每个切片比距离，取出最像的几条（TopK，默认 4）
  → 拼提示词：系统提示词 + 这几条原文 + 你的问题（以及上文）
  → 云上模型按「只能根据这些原文回答」来生成
  → 浏览器把 token 画出来，并展示引用
```

选「知识问答」时，跳过第一步。

模型看不到你的整个硬盘，也看不到没被检索出来的段落。它只看这次塞进提示词的那几段。所以：

- 问文档里有的内容，却答「未找到」：多半是没检索到那段。可以到检索实验室用同一句话看关键词和向量各自命中了什么，或把 TopK 调大一点。
- 答得很满、但引用对不上：是提示词约束没挡住。系统提示词在设置页，要求没有依据就说明未找到。

相似度是在 Node 里算的，没有另外的向量数据库。服务启动时，`sql.js` 会把整个 SQLite 读进进程；关掉 `npm run dev`，内存释放，磁盘上的文件还在。

## 6. 每个页面干什么

| 页面 | 你用它来 | 它不负责 |
| --- | --- | --- |
| 总览 | 看文档数、模型是否配好，点推荐问题进入对话 | 不改知识库 |
| 知识库 | 上传、抓网页、收藏、笔记、摘要、下载原文件、重索引、删除 | 不聊天 |
| 对话 | 正式问答。多会话，三个能力开关，限定文档，换回答风格 | 不上传文件 |
| 机器人 | 任何页面上的快捷提问。同一组开关，单独一条记录 | 不能管理文档 |
| 检索实验室 | 同一句话，左边关键词、右边向量，看检索本身准不准 | 不生成长回答。点「追问」才去对话 |
| 检索检查 | 预先写「这个问题应该落到哪篇文档」，跑一遍看排第几 | 不调用大模型写答案，只检查检索 |
| 工作流 | 把「检索 → 摘要 / 提取 / 比对」存成固定步骤，填一段任务再跑 | 不是对话里的智能体开关。智能体是四个现成工具；工作流是你自己排的步骤 |
| 设置 | 温度、TopK、阈值、系统提示词、清空知识库，以及同一组对话开关 | 密钥不要写在这里。密钥在 `server/.env` |

工作流的每一步都在服务端真实执行：检索读的是同一个 SQLite；摘要、提取、比对会再调一次大模型。

## 7. 数据分别存在哪

| 内容 | 位置 | 换电脑还在吗 |
| --- | --- | --- |
| 文档、切片、向量、摘要、笔记 | `server/data/docchat.sqlite` | 要拷这个文件 |
| 上传的原文件 | `server/storage/` | 要拷这个目录 |
| 模型 Key、是否用本地向量 | `server/.env` | 要自己再配，这个文件不进 Git |
| 对话会话 | 浏览器 `localStorage` 键 `docchat-sessions-v2` | 不在。可用对话页「导出 JSON」 |
| 机器人那一条记录 | 浏览器键 `docchat-robot-thread` | 不在 |
| 三个开关、温度、提示词、主题 | 浏览器键 `docchat-settings`、`docchat-theme` | 不在。新浏览器会回到默认：智能体、多轮、改写都开着 |

## 8. 想改界面时从哪几个文件看

| 你想改的 | 打开 |
| --- | --- |
| 对话页开关和发送 | `frontend/src/views/ChatView.vue` |
| 机器人面板 | `frontend/src/components/RobotAssistant.vue` |
| 三个开关的保存 | `frontend/src/stores/settings.ts` |
| 会话列表 | `frontend/src/stores/chat.ts` |
| 流式请求 | `frontend/src/api/chat.ts` |
| 问答顺序（智能体 → 改写 → 检索 → 生成） | `server/src/services/rag.service.ts` |
| 上传、抓取、下载用的原文件 | `server/src/services/ingest.service.ts`、`server/src/routes/docs.ts` |
| 表结构 | `server/src/db/schema.sql`、`docs/database.md` |

前端不会自己算向量，也不会把 API Key 放进浏览器。密钥只在 Node 进程里，从 `server/.env` 读取。
